# Two languages

Russian is primary; English is a switch away. Both are complete at all times -
there is no partial-translation state and no fallback chain to design.

## Two separate things

**Interface text** is a dictionary in the code: `ru` and `en` in
`app/src/lib/dict.ts`, read through `t()`. Every value is a plain string
(`Dict` is `Record<keyof typeof ru, string>`); the help panels are structured
parts in `app/src/lib/help.ts`, not dictionary entries. `Dict` is
derived from `ru`'s own shape and `en` is typed as `Dict`, so a key present in
one language and missing in the other is a compile error in both directions
(`tsc`/`svelte-check`, part of `npm run check`) - not a runtime report to read.

**Record text** is on the data: every record carries `en`/`ende` and `ru`/`rud`,
and `nameOf()` / `descOf()` pick by language. Russian falls back to English per
field (`it.ru || it.en`) because a record may arrive before its translation
does; English never falls back, because English is the source.

Do not merge these two. The dictionary is small, typed and reviewed; record text
is 1091 pairs maintained with the data.

**The share stubs (`i/*.html`, `tools/build-share-pages.js`) are Russian-only,
deliberately.** Every one of the 1091 pages is built from `it.ru || it.en`
and `it.rud || it.ende` regardless of which language a reader arrived from,
because they exist for link previews, and a preview needs one fixed language
rather than a guess at the reader's. Generating a parallel English set was
considered and rejected: it would double a 1091-file published artefact for
a preview string alone.

## Rules

- **Parity is enforced, not hoped for.** `Dict`'s own type makes a key present
  in one language and missing in the other a compile error - see above. Before
  R0c (issue 47) `tests/i18n.js` parsed `const T` out of the now-deleted
  `app.js` and failed the same way at runtime; the type system carries the
  rule now, so the runtime check was deleted with it.
- **The informational dead-key report did not survive the deletion**, and
  nothing replaces it: `tests/i18n.js` also listed keys with no call site
  without failing on them (`money_bag` and `money_coin` are reached as
  `'money_' + mode`, so "no call site" was not the same as "dead"). A dead key
  is now caught only by a human noticing. Checked by hand at R0c's sweep
  (`git show 92d6a4b:issues/47/sweep.md`, Part B): `money_bag`/`money_coin`
  are dynamic and in use; `srcFrame` was dead in the live app but is read at
  `label.ts:125` in the rewrite; `voaRecall`, `guessPrice`, `pcTh` and
  `printFoot` are dead on both apps and left alone.
- **The dictionary rename map**, both sides parsed by one walker at the
  deletion: live and `dict.ts` each carried 251/252 keys; 24 live keys were
  absent by name, of which 21 were renames with identical rendered values
  (`whatIsThis` -> `helpHint`, `setHome` -> `homeHint`, `isHome` -> `homeOn`,
  `tierLadder` -> `tier`, `pcTh` -> `eqTh`, `bumpTo` -> split into four
  phrases, `foot` -> split into `footBefore`/`footLink`/`footAfter`,
  `community` -> `communityLabel`, `tabs.*`/`pages.*` flattened). Zero keys
  present on both sides differed in value - the rename was purely
  structural, not a translation drift.
- **The switch is instant and total.** Interface, record names, record
  descriptions, stat words, table names, help panels, the document title and the
  chrome that has no text of its own (tab bar and language group `aria-label`s,
  the modal close button, the skip link).
- **`document.documentElement.lang` follows the choice.** Screen readers and
  hyphenation depend on it.
- **The choice is a preference**, stored in `dhloot.lang.v1`, validated on read
  (`ru` or `en`, anything else ignored). It is not in the URL: a link shared with
  a Russian-speaking party should open in the reader's own language.
- **Vocabulary follows [daggerheart.su](https://ru.daggerheart.su/)**, which is
  the translation the rest of the app quotes, so a weapon reads the same here
  and there. The equipment maps (`EQ_TYPE`, `EQ_TRAIT`, `EQ_RANGE`, `EQ_DT`,
  `EQ_BURDEN`, `EQ_CLS`, `EQ_LINE`) in `app/src/lib/i18n.ts` are meant to be
  the single place those words live, but `tools/build-share-pages.js` keeps
  a second, unguarded copy for the share stubs; nothing pins the two
  together (`docs/specs/DEBT.md` D38). Live audit, 2026-09-15:
  `en.daggerheart.su/frame/motherboard` names `f95` "Network Tether", the RU
  site uses `Сетевой Узел` / `сетевой узел` under category `Сетевые узлы` -
  not a literal translation of "tether", and why `Сетевой трос` was wrong.
- **Russian plurals are computed, not stored.** `moneyWord()` picks one of three
  forms by the last digit. Anything counting things in Russian needs the same
  treatment; do not write "3 монета".
- **No i18n framework.** A dictionary and a language flag are the whole
  requirement. Heavy i18n libraries are outside the approved dependency
  baseline.

## What a test has to cover

- both languages render every route without a missing-key hole
- switching language redraws record text as well as chrome
- `html[lang]` tracks the switch
- the choice survives a reload, and an invalid stored value falls back to `ru`

`tests/app/sweep.js` walks every address in both languages against `dist/`;
`tests/app/typo.js` checks the type scale in both.
