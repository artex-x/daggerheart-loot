# Two languages

Russian is primary; English is a switch away. Both are complete at all times -
there is no partial-translation state and no fallback chain to design.

## Two separate things

**Interface text** is a dictionary in the code: `T.ru` and `T.en` in `app.js`,
112 keys each, read through `t()`. Some values are HTML (the help panels), most
are plain strings.

**Record text** is on the data: every record carries `en`/`ende` and `ru`/`rud`,
and `nameOf()` / `descOf()` pick by language. Russian falls back to English per
field (`it.ru || it.en`) because a record may arrive before its translation
does; English never falls back, because English is the source.

Do not merge these two. The dictionary is small, typed and reviewed; record text
is 1061 pairs maintained with the data.

## Rules

- **Parity is enforced, not hoped for.** `tests/i18n.js` parses `const T` out of
  the source and fails if either language carries a key the other lacks, or if
  the code asks for a key neither has. Keep that check whatever the
  implementation becomes; a typed dictionary makes it a compile error instead,
  which is better.
- **The switch is instant and total.** Interface, record names, record
  descriptions, stat words, table names, help panels, the document title and the
  chrome that has no text of its own (tab bar and language group `aria-label`s,
  the modal close button, the skip link).
- **`document.documentElement.lang` follows the choice.** Screen readers and
  hyphenation depend on it.
- **The choice is a preference**, stored in `dhloot.lang.v1`, validated on read
  (`ru` or `en`, anything else ignored). It is not in the URL: a link shared with
  a Russian-speaking party should open in the reader's own language.
- **Vocabulary follows [daggerheart.su](https://ru.daggerheart.su/)**, which is
  the translation the rest of the app quotes, so a weapon reads the same here
  and there. The equipment maps (`EQ_TYPE`, `EQ_TRAIT`, `EQ_RANGE`, `EQ_DT`,
  `EQ_BURDEN`, `EQ_CLS`, `EQ_LINE`) are the single place those words live.
- **Russian plurals are computed, not stored.** `moneyWord()` picks one of three
  forms by the last digit. Anything counting things in Russian needs the same
  treatment; do not write "3 монета".
- **No i18n framework.** A dictionary and a language flag are the whole
  requirement. Heavy i18n libraries are outside the approved dependency
  baseline.

## What a test has to cover

- both languages render every route without a missing-key hole
- switching language redraws record text as well as chrome
- `html[lang]` tracks the switch
- the choice survives a reload, and an invalid stored value falls back to `ru`

`tests/audit2.js` walks every address in both languages; `tests/typo.js` checks
the type scale in both.
