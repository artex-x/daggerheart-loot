# 2026-10-07 - An item is read by its id by anyone; a list holds a live link

- Task: `persist-7h-homebrew-page` (owner, 2026-10-03, W1; the conversion and the deleted copy, owner, 2026-10-06; planner, the schema).
- Decision: a homebrew list entry is a live link to one item by its id, `list_entries.hb_item` (a foreign key with `on delete cascade`), whoever owns the item: an own add, an add from another user's share, «Сохранить себе» and an import all link. An edit of the item, its source or a card it names moves the revision of every list that links it; a delete removes the entry from every list. Any item is readable by anyone who holds its id, through `get_homebrew_item(uuid)` (`anon` and `authenticated`) and `get_homebrew_items(uuid[])` (`authenticated`, at most 1000 ids); nobody can list items, and no answer holds the owner. The byte limits are dropped, and `list_entries.snapshot` holds only null for this release, so a frontend-only revert keeps reading the lists (owner, 2026-10-07; `docs/specs/DEBT.md` D93); the lists file keeps its snapshots, written from the live item, and an import makes an own copy of each item the account does not hold. Migration `20261007130000_homebrew_links.sql` converted the stored rows: references and own-held frozen copies became links, and the one frozen copy with no holder was deleted (owner, 2026-10-06).
- `get_homebrew_item` also answers `updated_at`, the latest edit of the item, its source and the cards it names (owner, 2026-10-07): the item's address shows when it was last changed. It stays outside `revision`, which hashes only what the page draws, so a re-read redraws nothing for a time alone.
- Rejected: keeping frozen copies beside links (two kinds of entry, and a fixed typo stays in every list); a link by owner and key (a key is per owner, and an id needs no second column); a fixed copy for the one orphan row (owner: "it's mine, it's safe to delete").
- Accepted trade-off: an author's delete takes the item out of other users' lists; the list keeps a notice of it ("A list's change log shares the requests' view and the database's clean-up").
- Supersedes in part "Homebrew in the owner's lists is a live reference; a copy that leaves is frozen" (2026-09-26): a copy that leaves the account links the item instead of freezing it.
- Supersedes in part "A frozen copy embeds its source and cards; a reference must exist when written" (2026-09-30): no stored entry embeds a snapshot; the projection still embeds the item owner's source and cards.
- Supersedes in part "A frozen copy holds up to 131072 bytes; a card text holds 1500 code points" (2026-10-01): the bound holds for a lists file's snapshot only.
- Supersedes in part "A list's frozen copies hold up to 1048576 bytes together" (2026-10-02): the sum bound and its `limit_defaults` row are dropped.
- Supersedes in part "A lists file is version 2 only when it holds homebrew" (2026-10-02): every homebrew entry is written from the live item, and an entry the account does not hold imports as an own copy.
- Amends "Homebrew keeps the way open to shared books without building them" (2026-10-01): items are readable by id, `list_entries.hb_item` is the anticipated `item_owner`; books stay owner-only and subscriptions stay open.
