# 2026-10-21 - A script write to the test project is judged per file, like a push

- Task: `rule-2r-script-writes` (planner, 2026-10-21; owner, 2026-10-21: option A for the checkout).
- Decision: rule 2r allows a script or CLI migration write to the test project when `supabase/migrations` has no uncommitted change and every file of `HEAD`'s tree has the same blob, under the same name, on `origin/main` or in the tree of an approving report. One helper, `unknownMigrations` in `bash-guard.mjs`, judges the script path and the push path; only a push also takes a `refs/remotes/origin/*` ref. On 2026-10-21 no `refs/remotes/origin/*` ref held a migration blob that `origin/main` lacked (12 refs), so the narrower set denied no tree that the push rule allowed. `supabase/reversals/` is not judged: `migrate-test.mjs` never applies it, and `db-push.mjs` refuses an unpaired migration before any write.
- Decision (stale ref): the hook reads `origin/main` as it is and fetches nothing. `main` never moves back and a pushed migration never changes, so a stale ref only shrinks the known set and denies; the deny names `git fetch origin`.
- Decision (checkout; owner, 2026-10-21): rule 2r judges a script or CLI write only as one plain command - one segment; `npm run db:push`, `npx supabase`, the Supabase CLI or `node [--env-file=<path>] <toplevel>/tools/supabase/<script>` with no wrapper, assignment, npm flag, `--workdir` or `SUPABASE_WORKDIR` - and denies every other command that holds such a write (`migration-checkout-unpinned`), found by its tokens outside reader segments. Not found: a write inside a quoted span (`bash -c "..."`) or a heredoc body, which the sanitiser drops, or in `node -e`. With the per-file rule, the main checkout, whose files are all on `origin/main`, would otherwise allow another checkout's unreviewed migration. A `git push` after a `cd` is still judged against the cwd checkout.
- Rejected: whole-tree equality with an approved tree (each merge of a `main` with a new migration needed a fresh approval, 2026-10-21); every `refs/remotes/origin/*` ref as a source for a script write (a ref pushed before 2026-10-21, or outside `claude/**` and `main`, may never have reached `migrate-test`, and a script write applies the file at once); a `git fetch` inside the hook (network in a 10 s hook, and a stale ref fails toward deny); a list of the forms that move the directory (each review round found new groups: prefixed `cd`, `eval`, `if`/`for`, `source`, PowerShell script blocks, `Set-Item env:`); option B, a non-plain command judged by the whole-tree rule (it judges the cwd checkout of a moved command, so the defect stays open whenever that checkout's tree equals an approved tree, and two rules need tests and docs).
- Accepted trade-off: a tree that mixes `origin/main`'s files with an approved tree's was not reviewed as one tree; a push of the same branch already lets CI's `migrate-test` write it, so a deny of the script write adds no safety. The hook trusts the checkout's local `refs/remotes/origin/main` and its reports; a session can change either, so the rule stops a mistake, not a session that moves the ref, and an owner's force push of `main` can leave a stale ref with a file that `main` lost. A chained write, an approved one included (`git fetch origin && npm run db:push ...`), needs its own call, and a non-reader command that names `db-push.mjs` or `migrate-test.mjs` (`npx eslint ...`) denies.
- Amends "An agent pushes migrations to the test project only after an approving review" (2026-09-27): a script or CLI write takes the per-file rule, without other `origin/*` refs.
