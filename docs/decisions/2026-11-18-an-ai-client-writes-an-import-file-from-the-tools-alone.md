# 2026-11-18 - An AI client writes an import file from the tools alone

- Task: `api-usability` (owner-requested usability review of the API and MCP for autonomous AI clients, batch B3; implementer, 2026-11-18).
- Decision: the `check_file` description holds a minimal lists file and a minimal homebrew file and the two newest schema URLs; the answer names `file.schema` and each line's `level` and `id`. A new read-only tool `get_file_format` (`GET /api/v1/file-formats/{file_kind}`) answers the newest version, the schema URL, the rules, a field table and an example, from `apidata/file-format/<kind>.json` that the build writes from `schema/` (`docs/specs/CONTRACTS.md` section 6, "File checks" and "File formats"). Contract 1.5.0.
- Decision: a homebrew file's `enum` line names the allowed values, as JSON, in the app's own report (`lib/homebrewReport.ts`, the values from `lib/homebrew.ts` `ITEM_ENUMS` and `CARD_KINDS`), so the import panel and the API say the same in both languages; a lists file's `enum` line already named them.
- Rejected: the allowed values in an extra field of the API's check line only (the panel's text would still point at llms.txt, and two texts for one error could drift); a hand-written field table (it drifts from the schema; the build derives it, and a test holds its values equal to the parser's); the table at module load from imported schemas (every cold isolate would parse 37 KB of schema); the path parameter named `format` (the API has no `format` parameter: it serves the neutral record only) or `kind` (a record kind elsewhere); MCP resources (many clients do not read them).
