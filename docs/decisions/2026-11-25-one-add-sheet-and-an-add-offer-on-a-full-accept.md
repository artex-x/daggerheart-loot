# 2026-11-25 - One add sheet, and an add offer on a full accept of a hand-sent request

- Task: `73` (owner, 2026-11-24; Q1 = option C, Q4, Q5, Q6 and the held-key rule answered in chat).
- Decision: on `#/s/`, a signed-in reader's «В список» and the toast of a fully accepted request sent by hand («Сообщить владельцу») open one add sheet (`AddSheet`). The sender keeps the lines, the carried price and note, the linked records and `added` per sent id in memory only. Homes: `docs/specs/FEATURES.md`, "Purchase requests: the send" and "the add sheet"; `STATE.md`, "A purchase request leaves nothing in the browser"; `DESIGN.md`, "Sheet", "Selection bar" and "Toast".
- Rule: owner flow a (add to a list, then notify; `afterAdd`) gets the plain toast, because an offer would add the same items again and loop. The offer shows on a full accept only; a partial accept and a decline get the plain toast.
- Rejected, source of the counts: A, the taken counts in the decision message (a `SECURITY DEFINER` change to `purchase_requests_broadcast()`, a plan review, and an amendment of the 2026-10-29 payload rule, for a rare case); B, a read of the counts by request id (a new `anon` function with grants, caps and tests, about twice A).
- Rejected, the list choice: the last-used list preselected (too error-prone), the menu first and the sheet as a confirmation, today's menu with no preview. The sheet opens with no list chosen and «Добавить» is off until a choice.
- Rejected, a row tap that chooses and adds: the warning, the table and the toggles would never be seen first, and a wrong tap adds to the wrong list. A tap only chooses; a usual add is three presses (menu today: two).
- Held key: an entry the target list already holds stays unchanged (count, price, notes); the table row warns «Уже в списке: 2 шт. по 30 зол., ваша заметка останется», and every line held turns «Добавить» off. Rejected: add the counts (changes today's rule), replace the price and note (loses the player's data), a choice per row (more controls for a rare case).
- Copy toggles: «Копировать цену» and «Копировать заметку для игроков», in a fold «Что копировать», both on at each opening, component state only. A toggle off adds a new row without that field. The GM note is never copied and has no toggle (the add never copied it; a co-GM types it again).
- Data per flow: owner flow a copies the shared entry's price and note now; owner flow b copies those the bar showed at the send, not a price agreed at the table (the request's own `price_coins` is server-side and the sender cannot read it).
- Accepted trade-off: a second accepted request for the same items finds every line held, so the player raises the count on the list page; a reload, a closed tab or a down feed misses the offer (the 2026-10-29 trade-off); an add through a record's own menu is unknown to the sender, so its offer still shows.
- Accepted trade-off: the layout is one at every width, with the table and the toggles behind two folds closed at each opening and a warning line on the closed sheet; one press more to see the table, against one set of goldens and one code path.
- Amends "A sender hears a decision while the page stays open" (2026-10-29): the sending tab also offers the add on a full accept; the broadcast payload and the "nothing of a request is kept in the browser" rule stay.
