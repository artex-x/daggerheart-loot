# 2026-10-07 - A saved copy of another account's item keeps its key

- Task: `persist-7h-homebrew-page` (owner, 2026-10-07, the details of «Сохранить себе»; planner, the key).
- Decision: «Сохранить себе» on another account's item writes one own item in the default source under the item's own key, in one `import_homebrew` call: the `hb_` keys of the author's other items in `craft`, `craft_from` and `eq.line` are dropped, catalog ids stay, and the set and rule cards the record embeds are copied under their keys, or named when the reader already holds a card of that key. The same press relinks in place (`relink`) every row of the reader's account lists that links the item, so each row keeps its id, key, position, quantity, price and both notes. A reader who already holds the key sees «Сохранено» and makes no second copy. The account's read after the import decides whether the copy exists, so a lost answer whose rows landed is a save and a retry writes nothing twice.
- Rejected: a new key for the copy (the relinked row's key would move, the purchase request lines that name the key would stop resolving, and a second press would need a memory of what was saved); relinking only the open row (an own record wins a key, so every other row that links the author's item would draw the copy while staying linked to the author's item, and an author's delete would cascade those rows away with their quantity, price and notes); a relink as a remove and an add (it loses the position, the quantity, the price and both notes).
- Accepted trade-off: the copy loses its links to the author's other items; a reader who holds the key already, from an earlier copy or a file import of the author's items, cannot make a second copy.
- Refines "An item is read by its id by anyone; a list holds a live link" (2026-10-07): the one path by which a reader's row stops linking another account's item.
