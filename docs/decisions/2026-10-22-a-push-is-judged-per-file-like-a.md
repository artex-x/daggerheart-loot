# 2026-10-22 - A push is judged per file like a script write, and only as one plain command

- Task: `rule-2r-push-hardening` (owner, 2026-10-22: batch-only approvals, push sources as script writes, the push half of the checkout rule; mechanism by the planner).
- Decision (approvals): a report approves a migrations tree for rule 2r only with `Verdict: approve`, a `Reviewed:` sha and `Scope: batch <id>`, on the script path and the push path; a plan review approves nothing. On 2026-10-22 every one of 73 reports on this host had a `Scope:` line, and none of the four plan-scope approves was a schema batch's only approval.
- Decision (sources): a pushed file passes when its `<blob> <name>` is on `refs/remotes/origin/main`, on the `refs/remotes/origin/<branch>` that the push updates (an earlier push of that branch, judged by the rule, wrote it), or in an approved tree; a push that updates `main` also passes when `.check-cache.json` holds `by: "ci"` and the source's `commitKey`. No other `origin/*` ref and no upstream counts; the matching refspec `:`, `remote.origin.mirror`, a no-refspec push under `push.default=matching` or a `remote.origin.push`, and a bare-name refspec under `push.default=upstream` or a `remote.origin.push` are wide. On 2026-10-22 no ref held a migration blob that `origin/main` lacked (13 refs).
- Decision (checkout): rule 2r judges a push only as one plain command (the script shape's quote, segment and `rtk` tests, `git` with no global option but `-C <dir>` and the value-less ones but `--bare`, then `push`); a push in any other command, also one found behind a launcher or an option with a separate value by its tokens, denies `migration-push-unpinned` when a source or destination depends on the checkout (an erased quoted span after `push`, a `$(` or backtick in its statement, or `xargs` adds refspecs the hook cannot read, so each depends on it too) or a source holds a file on neither `origin/main` nor the branch it updates. A delete with a named destination and a dry run pass.
- Rejected: `origin/main` and approved trees only (every schema closeout would need the owner: the task-branch push after the task directory is deleted, and the squash push of `main`); every `origin/*` ref, or `origin/claude/*` refs pushed after 2026-10-21 (a sibling's unmerged migration passes); the upstream as the base (an upstream on a sibling passes); a scan of every worktree's `HEAD` for a non-plain bare push (a git call per kept worktree in a 10 s hook, and another clone is still not seen); a list of the forms that move the directory (three review rounds of the script rule found new groups).
- Accepted trade-off: a branch that carries another branch's unmerged migration needs a batch approve before its push (owner, 2026-10-22); a bare or `HEAD` push in a chain denies also when it changes nothing; a non-plain push of a named branch is read in cwd's repository, so a `cd` into another clone is not seen; a squash of a tree with a migration that `origin/main` lacks passes rule 2r only with the CI credit, not with a local `npm run check`, so the owner removes a differing file and the credit runs again; the destination's own ref and `.check-cache.json` are trusted as `origin/main` is: the rule stops a mistake, not a session that writes them.
- Amends "A script write to the test project is judged per file, like a push" (2026-10-21): a push takes no other `origin/*` ref, and a push in another command than one plain push denies when its source depends on the checkout or holds a file on neither `origin/main` nor its own ref.
- Amends "An agent pushes migrations to the test project only after an approving review" (2026-09-27): only a batch review approves.
