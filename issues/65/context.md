## Prior art in this repository (read before designing)

`git show 60172d3` added `.claude/settings.json`, `.claude/statusline.mjs` and
`.claude/usage-guard.mjs`; `git show 79e26c9` removed them. Both commit
messages are evidence and carry three facts that shape this task:

1. **Hooks fire in this desktop-app build.** The removal commit records a probe
   in which hooks fired nine times in a window where the statusLine command was
   invoked zero times. So a hooks setup is viable here; anything that depends on
   `statusLine` is not.
2. **Hooks receive no usage data.** The hook input is `session_id`,
   `prompt_id`, `transcript_path`, `cwd`, `permission_mode`, `effort`,
   `hook_event_name`, `agent_id`, `agent_type`. Do not design around cost,
   tokens or rate limits.
3. **Write hooks in Node, not `bash` + `jq`.** `jq` is not installed on this
   Windows box; the previous shell version's defensive `command -v jq || exit 0`
   made the guard exit silently every time - a guard that could never fire.
   Node is guaranteed present in this project and parses stdin JSON without
   shell-quoting hazards.

`.claude/settings.json` at 60172d3 is a working example of the file's shape
(`hooks` keyed by event, each entry `{ hooks: [{ type: "command", command }] }`).

## Tooling constraints that will bite

- `eslint.config.mjs` ignores `.claude/**` - hook scripts are not linted, and
  they sit outside every tsconfig, so `npm run typecheck` does not see them.
- `.prettierignore` excludes `*.md`, but **not** `.claude/**`. So
  `.claude/settings.json` and every `.claude/*.mjs` must be Prettier-clean or
  `npm run format:check`, the first step of `npm run check`, fails.
- Node >= 22, ESM (`"type"` is unset, so use the `.mjs` extension).
- Windows host. Paths arriving in hook payloads may be Windows-shaped; compare
  paths case-insensitively and normalise separators.

## Verifying the hooks on Linux without pushing

The selftest is inside `npm run check`, so a Windows-only assumption in it turns
CI red for everyone. It can be checked locally in seconds - Docker is available
on this box and both images are already built:

```sh
git archive HEAD .claude package.json | tar -x -C <scratch>/hookonly
docker run --rm -v "<scratch>/hookonly:/src:ro" node:22 bash -c   'cp -r /src /app && cd /app && git init -q . && git config user.email t@t.local    && git config user.name t && git add -A && git commit -qm init    && node .claude/hooks/selftest.mjs'
```

Measured 2026-09-09: reproduced CI's `#36`/`#42` failures on `773a2e6`
(192 passed, 2 FAILED) and confirmed `ed4f693` green (198 passed, 0 failed).

Two things that will bite:

- **Do not bind-mount the repository and run git inside it.** `git add -A` over
  a Windows bind mount of ~1000 files hangs for minutes. Copy into the container
  first - which is also why `tools/parity-ubuntu/` mounts `:ro` and copies to
  `/app`.
- Only `.claude/` and `package.json` are needed for the selftest, so archive
  those two paths rather than the whole tree. A full `npm run check` on Linux
  needs `node_modules`, which the `dh-parity:ubuntu24` image already has baked.
