## Blockers

1. **A file check reads bytes that are not UTF-8 as text and answers `ok`, where the app's
   import refuses the same file.** `rest.mjs` `readFile` (line 305) reads the body with
   `readText`, which decodes with a non-fatal `TextDecoder`, so a byte that is not UTF-8
   becomes U+FFFD. The import panel decodes with `bundle.ts` `decodeText` (strict) and answers
   `notJson` ("Это не файл JSON." / "This is not a JSON file.") for such bytes
   (`ImportFile.svelte` `textOf`). The probe shows a lists file with a CP1251 list name as
   `ok: true`, so a client is told that a file imports when the app refuses it. That breaks
   the operation's own promise ("as the app would", `openapi.json`; "the panels' own lines and
   refusal texts", B3 acceptance line 8), and the departure is not named. The same decode
   turns 32768 bytes that hold invalid sequences into more than 32768 bytes, so
   `overFileCap` answers 413 "past 32768 bytes" for a body that is not past it. The contract
   is not yet published (landing 3), so the fix is free now. Patch:
   - `preview/api/read.mjs` line 13: `export async function readText(res, max, decode = (b) =>
     new TextDecoder().decode(b))`, and line 40: `return { value: decode(bytes) };` (every
     other caller keeps the default).
   - `preview/api/rest.mjs`: `import { decodeText } from '../../app/src/lib/bundle.ts';` and
     line 305: `const got = await readText(request, FILE_CHECK_MAX, (b) => decodeText(b) ??
     '');` with the comment "Bytes that are not UTF-8 read as no JSON, as the import panel
     reads them (`ImportFile.svelte`)." The empty text then answers `not_json` with
     `importNotJson`, the panel's own refusal.
   - `preview/api/api.test.mjs`, "the file check": one case, the CP1251 lists file answers
     200 `not_json`, and 32768 bytes of `0xFF` answer 200 `not_json`, not 413.
   - `docs/specs/CONTRACTS.md` line 640, after "(413 `too_large` before any parse)": "; bytes
     that are not UTF-8 answer `not_json`, as the import reads them". The `openapi.json`
     `checkFile` description takes the same clause.
