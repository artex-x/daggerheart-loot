The dispatch questions:

- Exposure of the overload: none found. It is security invoker with a fixed `search_path`. It
  calls `get_shared_list(text, bigint)` (invoker), which calls the definer
  `get_shared_list(text)`, so the token check, the stopped-share null, R8's `img` and the GM-only
  drop stay in one body. `EXECUTE` is revoked from `public` and granted to `anon` and
  `authenticated`. `harness.test.mjs` pins `anon`'s set at seven, and both pin maps hold
  `prosecdef: false`. `rev` is the md5 of a snapshot that the same caller receives with `p_have`
  `{}`. A guessed `p_have` therefore reveals nothing, and a false one strips only the caller's own
  answer. Another signed-in user gets what `anon` gets. `p_have` that is not an object, is null or
  is over 64 KiB counts as `{}` (layer 3: `[]`, a string, null, 70 000 bytes).
- Stale or wrong snapshots: none found. The port copies `held` before the call and fills only
  an entry that the server sent with no `snapshot` key, from the held record whose `rev` equals
  the `rev` that the server sent with it. The server strips only where `p_have[hid]` equals the
  md5 of the current snapshot, so a filled record is the current record. An entry with no held
  record of that `rev` makes one whole read with `p_have` `{}`. A second unfillable answer is
  `{ ok: false }`, so the shown list stays. After `PGRST202` the port answers the older calls
  unfilled. `withSnapshots` rebuilds every entry with `snapshot` last on every path, so
  `sameProjection` stays exact. `SharedView` sends the held map only from a `ready` page of the
  same token, and `#readSeq`/`#appliedSeq` drop an older answer in `open()` and `refresh()`.
  The fake strips and fills by the same rule (a marked held snapshot proves the strip).
- Two tabs and offline: the held map is in memory, one for each `SharedView`. It is never stored,
  so two tabs cannot affect each other. Offline is a failed read, so the shown list stays.
  `sharedHaveGone` is for each port instance and stays until a reload. A transient `PGRST202`
  (for example a schema cache reload) gives a correct page that downloads more, which plan 4.2's
  revert row accepts.
