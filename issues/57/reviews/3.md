## Blockers

**B1. The alternate tables lost their source tag.** `app/src/lib/rowTags.ts`,
`MANY_BOOKS` leaves out `alt_item` and `alt_consumable`, so `hiddenTags` hides the source
on both. `data.json` holds 60 Core and 60 Hope & Fear records in each table, mixed in
every rarity column. Before this batch every row named its book. Now nothing on the page
names it. `FEATURES.md` hides the source only "on a one-book table". `rowTags.test.ts`
has no alternate case.
Fix: add both ids to `MANY_BOOKS`, add a `rowTags.test.ts` case, re-seed the alternate
table goldens.

**B2. `/s/` has a new invisible tab stop for every reader.** `SelectionBar.svelte:78`
draws «Все» on `total > 0` and does not test `idle`. The shared page keeps the bar
mounted with `.vh` while nothing is ticked. `.vh` only clips, so the box stays focusable.
Proof: `tests/app/snapshots/_s_player_token_1.txt:39-40` shows `region "Выбранные записи"`
with `checkbox "Выбрать все"` at zero ticks. A keyboard reader lands on a control with no
visible focus (WCAG 2.4.7), and Space ticks every row. A screen reader also meets two
«Выбрать все». The goldens were re-seeded with this defect.
Fix: `{#if total > 0 && !idle}`, a `selectionBar.test.ts` case for the idle state,
re-seed the idle `/s/` goldens.

**B3. The search highlight splits names.** `RowMain.svelte` draws the name runs and
`<mark>` directly inside `.row-main .rt b`, which is `display: flex; gap: 8px`. Each run
becomes a flex item with an 8 px gap. Evidence: `mocks/3/built/catalog-searched__1180__ru.png`
reads «Меч  -Хлыст», not «Меч-Хлыст». A match that ends inside a word splits that word.
The acceptance line for C59 is not met.
Fix: wrap the runs in one `<span>` inside the `b`, so `rnum`, the name and `rtail` stay
the three flex items. Add a case that all runs share one parent.

**B4. The picker cuts most table names at 360.** The picker is the page's only visible
name below 761 px, and about 100 px is left for it beside the view switch and «Ещё».
Evidence: `mocks/3/built/catalog-grid__360__ru.png` reads «Wondr...». Deviation 6 fixed
«Оружие» only: the evidence set shoots the picker on `eq_weapon` alone. Any caption past
about 8 characters cuts, so most of the 19 tables cut. This defeats D10: «Core · Предметы»
and «Hope & Fear · Предметы» exist to differ. It also fails the Clarity Rule on the phone,
which is the primary device.
Recommended fix: two lines at `--t-body`, clamped, with `overflow-wrap: anywhere`. Two
lines of 16 px fit the present row height, so the first-screen offset should not move.
Accepted trade-off: the picker type is smaller than the mock's `--t-section`.
Add 360 evidence for the three longest captions in RU and EN.

**B5. The selection bar covers the bottom of the filter column.** `.fcol` has
`max-height: calc(100dvh - var(--anchor-top) - 16px)` and does not subtract the bar.
The bar is 69 px at 1180, so about 53 px of a stuck column sit under it. The column
scrolls inside itself, so `html`'s `scroll-padding-bottom` does not reach it. The last
chip row of a tall column (`eq_weapon`) cannot clear the bar, and a focused chip there is
covered (WCAG 2.4.11). The acceptance line "no tab stop hides under it" fails for this
state. No suite walks the column in the selection mode: `FOCUS_WALK` runs with the mode off.
Fix: subtract `var(--selbar-h, 0px)` in the `max-height`. Add one case to `states.js`.

## Risks

**R1. A press on an «Ещё» item drops the focus (rule 20).** `TablesPage.svelte:699-728`
sets `moreOpen = false`, the pressed item unmounts and the focus falls to `body`.
`Menu.svelte` returns the focus to its control on Escape only. The earlier callers
navigate, so this is the first menu that stays on the page. The keyboard reader restarts
from the top after «Ссылка на таблицу» or the pin.
Fix: focus `moreButton` in each handler. Add the assertion to the test at
`tables.test.ts:1697`.

**R2. Open state survives a band change.** See item 4 under "Deviations". `filterOpen`
(`TablesPage`), `moreOpen` (`TablesPage`) and `picking` (`TableNav`) keep their value while
their branch is gone, so a rotation back reopens the sheet or the menu with no press. The
removed dialog fires no `close`, so `onclose` does not run and the focus falls to `body`.
Fix: reset the three flags when `app.band` changes, and move the focus to the first
«Все» of the column, or to «Фильтры».

**R3. «Выбрать» on an empty table drops the focus.** With no drawn rows the bar draws no
«Все» (deviation 4), so `startSelecting` finds nothing and the removed button leaves the
focus on `body`. The mode also has nothing to select there.
Fix: draw «Выбрать» only while `drawnIds.length > 0`.

**R4. The empty state can print an empty quotation.** `chosenLabels` drops a picked value
that no row offers, while `passes` still applies it. Example: `/tables/eq_weapon/f_tier-9`,
or a `f_src-hb` link opened signed out. Then `chosen` and `terms` are both empty and
`emptyCause` reads «Нет совпадений с «» в названиях и описаниях этой таблицы.». The
column shows no pressed chip and no «Сбросить» either.
Fix: draw no cause when both are empty. Pass the query to `replace` through a function,
because `$&` and a literal `%v` in the query change the sentence.

**R5. The selection bar has no height cap.** Plan section 10, standing check 1 states
`max-height: 45dvh` with its own scroll. `SelectionBar.svelte` has neither. The shared
page's bar with the send line or the notify question is the tall case, in landscape most.
Warning: `overflow: auto` on `.selbarwrap` clips the `AddToList` menu that opens upward.
Recommended: measure at 640x360, put the scroll on the action row if needed, and record
the outcome in the handoff.

**R6. Two scale rows have no proof.** The States table names `tables.test.ts` with 458 ids
(«Выбрано: 458») and 300 own items. Neither fixture exists in `tables.test.ts` or
`selectionBar.test.ts`.
Fix: add the 458 case to `selectionBar.test.ts`, and add or strike the 300 row with a reason.

**R7. Two mock departures at 1180 are not named.** Mock 3 puts the search row in the rows
column, so the filter column starts under the tabs. The build runs the search row across
the page, above the column. Mock 3 also keeps only the count at 1180 («на 1180 они видны в
колонке фильтров»). The build repeats the values, which takes width from the search.
Recommended: keep the search row where it is, because the offset is better (250 against
269), and name it in the handoff. Draw the values only below `wide`, and change the
one `FEATURES.md` line. Accepted trade-off: the column stays the only place that shows
the picks at wide.
