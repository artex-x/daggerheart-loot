# Phase 8 critique - code hygiene

Read-only sweep. Scope: comments, language policy, style consistency,
repository structure, dead code. Base commit `f53f44d`; the migration's
deletion commit is `23c00a6` (R0c).

Method notes that matter for reading the numbers below:

- "Cyrillic lines" are counted with `rg '\p{Cyrillic}'` per file, so a line
  carrying both a Russian failure message and a Russian product literal is
  counted once. The (a)/(b)/(c) split is measured by context greps
  (`ok(` / `console.log(` / `throw` for (a), leading `//`/`*`/`/*` for (c))
  plus continuation lines, then judged. Treat the per-file totals as exact and
  the splits as +/- a few.
- `tests/app/snapshots/*.txt` (11,503 Cyrillic occurrences, 125 files) are
  **generated goldens**, regenerated by `node tests/app/golden.js --update` and
  protected by `.claude/hooks/edit-guard.mjs`. They are category (b) by
  construction and are excluded from every count below.
- Nothing here proposes changing a public contract, and nothing proposes
  deleting `issues/47/`.

### H1 - Russian in test and tool messages (the owner's explicit ask)

**Where:** `tests/**`, `tools/**`. Full inventory in the table further down.

**Problem.** `CLAUDE.md` line 139: "Source, identifiers, tests, and developer
docs are English. Product text may be Russian." About **530 lines of code**
break this: every failure message, `console.log` heading and suite display name
in the node suites and most of the browser suites is Russian prose about the
test, not about the product. Representative sites:

  (`'корень отдал ' + index.status + ', а не 200'`,
  `'сайт опубликован верно: ' + ROOT`). This file is the last step of the
  `deploy` job; a red deploy in CI prints Russian to a log.
- `tests/derived.js`, `tests/dataint.js` - ~180 Russian assertion messages
  between them, plus ~130 lines of Russian comment.
- `tests/app/print.js` (~170), `tests/app/states.js` (~76),
  `tests/app/golden.js` (16), `tests/app/hues.js` (~13),
  `tests/app/contracts.js` (~12), `tests/app/sweep.js` (~13).
- `tests/run-all.js:41-58` - the 18 suite display names
  (`'dist/: обход страниц 1180'`). Safe to translate: `keyOf`/`fileOf` key off
  `s[0]`, never `s[1]`, so no filter string, artifact name or CI reference moves.
- `tests/app/lib.js:21` - `'dist/index.html не собран - сначала npm run build'`,
  the one-sentence guard every browser suite hits first.
- `tools/build.js:26` - `console.log(name + ' — ' + ... + ' КБ')`, a build tool
  reporting kilobytes in Russian (and with an em dash; see H13).

**Why it matters.** The owner asked for it directly. Beyond that: these are the
messages a CI log shows, and `tests/` and `tools/` are the two trees with no
lint and no format gate (H11), so the drift has nothing stopping it.

**Smallest fix.** Translate the (a) column only. Leave every (b) string
byte-for-byte.

**Effort/value:** L / high. **Not one mechanical batch** - see the judgment
under the table.

### H6 - `app/src/styles/tokens.css:63-65` overclaims, and sits above the wrong declarations

**Where:** `app/src/styles/tokens.css:63-65`.

```
/* The page heading, taken off the live app's `.page-h` rather than invented:
```

**Smallest fix.** Move the block down to sit immediately above line 70, and
replace the last sentence with what is true: "`tests/app/typo.js` measures the
rendered sizes against its own scale list; a new step here has to be added

**Effort/value:** S / medium-high (it is a comment that would mislead somebody
into thinking a token change is guarded).

### H12 - component test filenames drift between two conventions

**Where:** `app/src/components/`.

Two tests match their component's PascalCase name - `Chip.test.ts`,
`OrGrid.test.ts`. Fourteen do not: `a11y.test.ts`, `alt.test.ts`,
`button.test.ts`, `listPage.test.ts`, `lists.test.ts`, `listsPage.test.ts`,
`printPage.test.ts`, `record.test.ts`, `roll.test.ts`, `searchPage.test.ts`,
`sections.test.ts`, `sharedListPage.test.ts`, `shell.test.ts`, `std.test.ts`,
`tables.test.ts`.

**Problem.** Neither convention is wrong, but having both means you cannot
answer "where is `Button.svelte` tested?" by looking - `button.test.ts` covers
it, `Chip.test.ts` covers `Chip.svelte`, and `lists.test.ts` versus
`listsPage.test.ts` versus `listPage.test.ts` is three near-identical names for
three different surfaces. `app/src/lib/` is perfectly consistent by contrast
(`foo.ts` / `foo.test.ts`, every pair), which is what makes the components
directory read as drift rather than as a deliberate second scheme.

Renaming is safe: `docs/specs/COVERAGE.md` and `vite.config.mts:169`'s
`perFile: true` enforce coverage per source file reached by *a* test,
explicitly "not by a matching filename".

**Smallest fix.** Pick the lowercase-subject convention (14 files already use
it) and rename the two outliers to `chip.test.ts` and `orGrid.test.ts`. Two
renames, no import changes (nothing imports a test file).

**Effort/value:** S / low-medium. A judgment call the owner should make; do not
do it unasked.

**This is not one mechanical batch.** Three reasons:

1. **(a) and (b) share lines in the two biggest files.**
   `tests/app/print.js:269` asserts that a card's name equals a Russian product
   string *and* reports the mismatch in a Russian sentence, on one line. The
   first string is load-bearing; the second is the message. A find-and-replace
   over Cyrillic would corrupt the expected value, and the failure would then
   look like a product regression. `tests/app/states.js` is the same shape
   (~76 of 142). Those two files need per-site judgment, roughly 250 sites.
2. **A vocabulary trap.** `tests/app/print.js:1037` and
   `docs/specs/COVERAGE.md:83` say `sheetCounts`/`printMedia` "stay
   Russian-only" and that R0c added an "English pass". **That is about the UI
   language the suite drives the app in, not the language the test is written
   in.** Whoever does H1 must not read those notes as permission to leave the
   messages, nor as an instruction to add English UI runs. Worth disambiguating
   both to "driven in Russian only" in the same pass.
3. **Four files are genuinely mechanical** and can go first as one small,
   low-risk batch: `tools/check-site.mjs` (17), `tests/app/golden.js` (16),
   `tests/app/lib.js` (1), `tools/build.js` (1), plus `tests/run-all.js`'s 18
   display names (verified safe: `keyOf` and `fileOf` key off `s[0]`, never
   `s[1]`). About 53 lines, with no product string anywhere among them.

**Suggested split:** B1 the mechanical 53 above plus `tests/stub.js`;
B2 `tests/dataint.js` and `tests/derived.js` (the ~180 node-suite messages,
plus the (c) decision); B3 `tests/app/print.js`; B4 `tests/app/states.js`;
B5 the small browser suites (`hues`, `contracts`, `typo`, `sweep`, `driver`).
Each is gated by `node tests/run-all.js <suite>` plus, for B2,
`node tests/derived.js` - messages only change on the failure path, so a green
run before and after is the whole proof.

**On (c), the 166 Russian comments.** `CLAUDE.md` says developer docs are
English, and a comment in a source file is developer documentation. But the
owner's phrasing was "make sure all code e.g. tests use english", which points
at (a) first. `tests/derived.js` alone carries about 125 of the 166, and they
are dense, load-bearing prose - why a threshold exists, which defect a check
guards, which earlier version of a check was wrong and why. Translating them is
a real writing job with a real chance of losing meaning, not a mechanical pass.
**Recommendation:** do (a) first and in full; put (c) behind it as its own
decision, file by file, and do not bundle the two. `tools/derived.js` (8 lines)
and `tests/run-all.js` (~12) are cheap enough to take with their file's (a) pass.
